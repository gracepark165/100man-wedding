# 비용 신뢰도 개선: 설계

- 작성일: 2026-11-13
- 상태: 검토 대기
- 계기: 외부 검토 의견(지원금 표시, 예산 근거, 절감 옵션과 지원의 관계, 날짜 계산)

## 0. 원칙

**확인되지 않은 돈은 확정된 돈처럼 보이지 않게 한다.**

- 기본 숫자는 지원 전 금액이다.
- 지원금과 미확인 단가는 "시나리오"나 "미확인"이라는 이름표를 붙여 따로 보여준다.
- 이 사이트는 제도의 적용 여부를 판단하지 않는다. 공식 공고를 확인하도록 안내한다.

## 1. 날짜 규칙 통일

- 할 일 기한을 개월 수(`m`)가 아니라 **예식 n일 전(`days`)**으로 정한다.

| id | days | 이름표 |
|---|---|---|
| consult | 180 | 6개월 전 |
| share | 90 | 3개월 전 |
| venue | 75 | 2개월 반 전 |
| meal | 60 | 2개월 전 |
| attire | 45 | 1개월 반 전 |
| invite | 30 | 1개월 전 |
| staff | 21 | 3주 전 |
| count | 14 | 2주 전 |
| support | 7 | 1주 전 |
| final | 7 | 1주 전 |
| register | 0 | 예식일 전후 |

- 이름표는 `days`에서 만든다.
  - 30일 미만이고 7로 나누어떨어지면 "n주"
  - 그 밖에는 30일을 1개월로 보고 "n개월" 또는 "n개월 반"
  - 0이면 "예식일 전후"
- 기한 날짜 = 예식일 − `days`일. 달력 날짜로 계산해서 월말, 연도 변경, 윤년에서도 정확해야 한다.
- 순서 규칙의 "같은 단계 안에서 `m`이 큰 것 먼저"는 "`days`가 큰 것 먼저"로 바꾼다. 기한 없는 할 일(`budget`, `res-check`)은 그대로 기한 없음이다.

## 2. 지원금은 시나리오로

### 2.1 데이터 분리: `src/support.json`

```json
{
  "name": "서울시 '더 아름다운 결혼식' 비품비 지원",
  "max": 100,
  "years": {
    "2026": {"apply": "2026-05-28 ~ 2026-11-28", "checked": "", "url": "공식 공고 주소"}
  },
  "eligibleItems": ["decor"],
  "eligibleNote": "협약업체 결제분만 지원돼요. 어떤 품목이 대상인지는 공고로 확인하세요."
}
```

- 예식일의 연도가 `years`에 없거나 `checked`가 비어 있으면, 그 해는 **"공고 확인 전"**으로 본다.
- 지원 대상 품목(`eligibleItems`)은 확인 전까지 보수적으로 **장소 장식(`decor`)만**으로 본다.
- 운영자가 공고를 확인하면 이 파일만 고친다. `build.py`가 사이트에 넣는다.

### 2.2 계산

| 값 | 정의 |
|---|---|
| `gross` | 지원 전 합계 |
| `total` | `gross`. 이제 기본 합계에서 지원금을 빼지 않는다 |
| `over`, `reserve`, 판정, 오리 장면 | 모두 `total`(지원 전) 기준 |
| `supportScenario` | 서울, 공공예식장, 거주지 '예' 또는 '모르겠어요'일 때만 계산. `min(max, 지원 대상 품목 금액 합)` |
| `scenarioTotal` | `gross − supportScenario` |
| `supportStatus` | 지원 상태. 아래 셋 중 하나 |

`supportStatus`의 값:
- `'confirmed-notice'`: 그 해 공고 확인됨
- `'unconfirmed'`: 공고 확인 전
- `'unknown-residence'`: 거주지 '모르겠어요'

### 2.3 화면

- 예산 탭의 지원 줄을 "차감"에서 **시나리오 상자**로 바꾼다.
  - 문구: "지원이 확정되면 {scenarioTotal} (−{supportScenario})"
  - 상태 이름표: `공고 확인 전` / `2026년 공고 기준` / `거주 조건 확인 필요`
  - 대상 품목 설명과 공식 링크를 함께 둔다.
- 요약과 오리 말풍선에서는 지원 전 금액만 말한다. 시나리오가 있으면 "지원 확정 시 {scenarioTotal}"을 한 줄 덧붙인다.
- 지원 신청 기간 문구는 코드에 적지 않고 `support.json`에서 읽는다. 예식 연도의 정보가 없으면 "{연도}년 공고는 아직 확인 전이에요. 공식 공고를 확인하세요."라고 쓴다.
- 비서의 `budget` 할 일은 지원 전 금액 기준이다. 이유 문구는 "지원 전 합계가 …이라 …"이고, 시나리오가 있으면 "지원이 확정되면 {scenarioTotal}이에요"를 덧붙인다.

## 3. 절감 옵션과 지원 연동

- 절감 옵션에 `affects` 필드를 둔다. 예: 장식 직접 준비는 `decor`에 영향을 준다.
- "모두 적용하면" 계산에서, 적용한 옵션이 지원 대상 품목을 줄이면 그만큼 지원 시나리오를 다시 계산한다.
  - 장식 직접 준비는 협약업체 결제가 아니므로, 장식에서 줄인 금액만큼 지원 대상에서 뺀다.
- 그런 옵션 옆에는 "직접 준비하면 비품비 지원 대상에서 빠질 수 있어요"라는 표시를 붙인다.
- "모두 적용하면" 문구:
  - 시나리오가 없으면: "모두 적용하면 합계가 약 {A}가 돼요"
  - 시나리오가 있으면: "모두 적용하면 지원 전 약 {A}, 지원 확정 시 약 {B}"

## 4. 예산 항목 근거

### 4.1 데이터: `src/costs.json`

예산 줄마다 근거를 담는다.

```json
{
  "decor": {"basis": "보도", "src": "세계일보 공공예식장 기사", "url": "…", "checked": "2026-11-09", "assume": "공공예식장은 빈 공간이라 꽃·소품 장식이 필요", "required": true},
  "meal":  {"basis": "예시", "src": "", "url": "", "checked": "", "assume": "1인 단가 × 인원, 지역 물가 반영", "required": true}
}
```

- 키: `rent, meal, decor, staff, dress, makeup, photo, flower, ring, card, register`
- `basis`는 `공식`, `보도`, `견적`, `예시` 중 하나다.
- `checked`가 비어 있거나 `basis`가 `예시`인 줄은 **미확인**이다.

### 4.2 화면

- 예산 줄마다 작은 이름표를 붙인다. 예: `예시 단가`, `보도 · 2026-11-09`
- 줄을 누르면 가정, 출처 링크, 필수 여부가 펼쳐진다.
- 예산 탭 위에 "이 중 미확인 비용 {합}"을 보여준다.
- 미확인 줄이 하나라도 있으면 상태 문구에 "예시 단가가 포함된 추정치예요"를 붙인다.

## 5. 5명 관찰 실험 (문서)

`docs/research/2026-11-usability-test.md`

| 항목 | 내용 |
|---|---|
| 대상 | 서울에서 소규모 예식을 검토하며 공공예식장 이용 조건을 비교하는 예비부부 5명 내외 |
| 과업 | ① 자기 조건으로 결과 보기 ② 지원금이 확정인지 설명하기 ③ 문의할 장소 후보 2곳과 물어볼 질문 고르기 ④ 지금 할 일 하나 말하기 |
| 기록 | 과업 완료 여부, 비용을 잘못 이해한 횟수와 내용, 막힌 지점, 걸린 시간, 한 말 |
| 해석 한계 | 이 표본으로 수요나 일반적 효과를 판단하지 않는다 |

기록표 양식(표)도 함께 넣는다. 앞선 설계의 "8주 20쌍" 지표 전에 이 실험을 먼저 한다.

## 6. 테스트

1. 예식일 2027-02-13이면 1주 전 할 일은 2027-02-06, 3주 전은 2027-01-23이다. 2028-03-07이면 1주 전은 2028-02-29(윤년)다.
2. 서울·공공·거주 '예'인 예시 결과의 기본 합계는 지원 전 금액이고, 시나리오 상자에 지원 확정 시 금액과 `공고 확인 전` 이름표가 있다.
3. 예식 연도가 `support.json`에 확인 날짜와 함께 있으면 `{연도}년 공고 기준` 이름표가 나온다.
4. 판정, 오리 장면, 비서의 `budget` 할 일은 지원 전 금액 기준이다.
5. "모두 적용하면" 계산에 장식 직접 준비가 들어가면 지원 시나리오가 줄어든다. 해당 옵션 옆에 경고가 있다.
6. 예산 줄마다 근거 이름표가 있고, 미확인 비용 합계가 맞다.
7. `costs.json`이나 `support.json`이 깨졌거나 키가 빠졌으면 빌드가 실패한다.
8. 기존 테스트는 지원금 차감을 기대하던 부분만 새 규칙에 맞게 고치고, 나머지는 그대로 통과한다.
