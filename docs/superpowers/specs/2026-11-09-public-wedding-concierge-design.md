# 공공예식장 커플 전담 서비스: 첫 버전 설계

- 작성일: 2026-11-09
- 상태: 검토 대기
- 출발점: `100만원으로 결혼하기` 사이트 (`back-navigation` 브랜치의 되돌아가기 개선 포함)

## 0. 목표와 전제

| 항목 | 내용 |
|---|---|
| 목표 | 실제 창업·수익화 |
| 고객 | 공공예식장(우선 서울시 '더 아름다운 결혼식')을 고려하는 예비부부 |
| 제공 가치 | 지원 자격 확인 → 장소 비교 → 상담 신청 → 협력업체 계약 → 준비 일정·지출 관리를 한곳에서 안내 |
| 수익 가설 | 1차: 가격을 공개한 업체와의 소개 제휴 수수료. 2차: 지자체 홍보·위탁. 보조: 커플 대상 유료 동행 상품 |
| 운영 여건 | 운영자 1명, 주 5~10시간. 코딩은 Claude와 함께 진행 |
| 첫 버전 원칙 | 서버 없는 정적 사이트(입구·진단) + 운영자가 카카오톡으로 직접 돕는 상담(검증). 반복되는 일만 나중에 기능으로 만든다 |

### 참고 사례에서 가져온 판단

- Zola: 계획 도구는 무료로 주고 고객을 붙잡는 장치로 쓰며, 수익은 그 뒤 거래에서 낸다 → 핵심 도구 무료 유지.
- The Knot·WeddingWire: 업체 연결(리드) 판매 모델은 "업체 영업 연락" 불만이 크다 → "영업 연락 없음, 가격 공개 업체만"을 원칙으로 한다.
- 공정위 결혼서비스 가격표시 의무(2025.11~): 공개율이 약 53%에 그친다 → 가격을 공개한 업체만 제휴 대상으로 삼는 것이 차별점이다.
- 서울시 '더 아름다운 결혼식': 공공예식장은 61곳이고 2027년 말까지 상시 접수한다. 상담 신청 후 협력업체 계약까지 과정이 길다 → 이 사이 과정이 우리 서비스가 들어갈 자리다.

## 1. 첫 버전 범위

### 사이트에서 할 일 (파일 하나, 서버 없음)

1. 거주지 질문 추가: 지원금 대상인지 확인한다.
2. 장소 탭에 실제 공공예식장 목록을 보여준다.
3. 결과 공유 링크를 만든다.
4. 체크리스트를 저장하고 캘린더로 내보낸다.
5. 1:1 준비 도우미 신청 카드를 둔다(구글폼으로 연결).
6. 방문 통계를 4곳에서 센다(GoatCounter).

### 운영자가 할 일

- 신청 커플과 카카오톡 채널로 1:1 대화하며 준비를 돕는다(3장).
- 진행 단계와 실제 지출을 스프레드시트 한 장에 기록한다.
- 가격을 공개한 업체 3~5곳과 소개 코드 방식으로 제휴한다.

### 일부러 빼는 것

로그인, 결제, 자동 알림, 앱, 후기 게시판. 수요가 확인된 뒤 만든다.

### 성공 기준 (공개 후 8주)

| 지표 | 목표 |
|---|---|
| 1:1 도우미 신청 | 20쌍 |
| 실제 공공예식장 상담 신청까지 간 커플 | 10쌍 |
| 업체 소개 성사 | 3건 |
| "유료라도 쓰겠다"는 응답 | 신청자의 30% 이상 |

예식까지는 몇 달이 걸리므로 8주 안에는 중간 단계까지 가는지로 판단한다.

## 2. 화면 흐름과 데이터

```
처음 화면 → 질문 6개 (+ 서울이면 거주지 질문 1개) → 결과 [예산 | 장소 | 일정]
                                                      │
                          공유 링크 · 캘린더 내보내기 · 1:1 도우미 신청
```

### 2.1 거주지 질문

- 조건: 지역을 `서울`로 고른 경우에만 세부 지역 다음에 나온다.
- 질문: "두 분 중 한 분이라도 서울에 주민등록이 되어 있나요?"
- 답: `예`(`y`) / `아니요`(`n`) / `잘 모르겠어요`(`u`).
- 효과:
  - `y`: 지금 코드의 서울시 비품비 지원(최대 100만원) 줄을 적용한다.
  - `n`: 지원 줄을 빼고, 지원 대상이 아니라고 한 줄로 알린다.
  - `u`: 지원 줄을 "조건 충족 시"로 표시하고 자격 조건을 한 줄로 안내한다. 합계에는 넣지 않는다.
- 진행 점의 개수는 서울이면 7개, 다른 지역이면 6개다.
- 지역을 서울이 아닌 곳으로 바꾸면 거주지 답을 지운다.
- 되돌아가기 동작(결과에서 항목만 고치기, 진행 점 이동, 뒤로가기)은 그대로 적용한다.

### 2.2 공공예식장 목록

- 데이터 파일: `src/venues.json`. 운영자가 코드를 몰라도 이 파일만 고치면 된다. `build.py`가 빌드할 때 사이트에 넣는다.
- 항목 구조 (값은 예시):

```json
{
  "id": "namsan-hannam",
  "name": "남산 한남웨딩가든",
  "gu": "용산구",
  "area": "mp",
  "cap": [30, 100],
  "fee": "무료",
  "food": "지정업체",
  "open": "예식 6개월 전",
  "url": "공식 안내 페이지 주소",
  "checked": "2026-11-09"
}
```

| 필드 | 뜻 |
|---|---|
| `area` | 세부 지역 값(`gn`, `mp`, `gs`, `gb` 등)과 같다 |
| `cap` | [최소, 최대] 수용 인원 |
| `fee`, `food`, `open` | 화면에 그대로 보이는 짧은 글 |
| `checked` | 운영자가 마지막으로 확인한 날 |

- 정렬: (1) 고른 세부 지역과 같은 곳, (2) 하객 수가 `cap` 안에 드는 곳, (3) 나머지 순서로 보여준다.
- 수용 인원을 넘는 곳은 "하객 수보다 작아요" 표시를 붙여 아래에 둔다.
- 목록 아래에 가장 오래된 `checked` 날짜를 "정보 기준일"로 표시한다.
- 서울이 아닌 지역에서는 지금처럼 유형 안내와 찾는 방법만 보여준다.
- 첫 데이터: Claude가 서울시 공식 자료로 초안을 모으고, 운영자가 수용 인원·대관료를 직접 확인한 뒤 공개한다.

### 2.3 결과 공유 링크

- 형식: `?d=q1&r=seoul&s=gs&g=20&v=public&m=box&res=y`
- 키: `d` 시기, `r` 지역, `s` 세부 지역, `g` 하객, `v` 장소, `m` 식사, `res` 거주지(서울일 때만).
- 이 주소로 들어오면 질문 없이 바로 결과를 보여준다.
- 값이 하나라도 맞지 않으면 처음 화면으로 가고, 맞는 값은 미리 선택해 둔다.
- 결과 화면이 바뀌면 주소도 `history.replaceState`로 맞춘다. 뒤로가기 기록과 충돌하지 않게 한다.
- '결과 공유' 버튼:
  - `navigator.share`가 되면 휴대폰 공유창을 연다.
  - 안 되면 링크를 복사하고 "링크를 복사했어요"라고 알린다.
- 이름, 연락처 등 개인정보는 주소에 넣지 않는다.

### 2.4 일정 탭

- 체크 저장:
  - `localStorage`에 공유 링크 키와 같은 답 조합별로 저장한다.
  - 모든 읽기·쓰기를 try/catch로 감싸, 저장이 막혀도 화면은 정상 동작하게 한다.
- 캘린더 내보내기:
  - '내 캘린더에 넣기' 버튼으로 `.ics` 파일을 받는다.
  - 할 일마다 종일 일정(VEVENT) 하나를 만든다. 날짜는 지금 일정 계산과 같다.
  - 이미 지난 할 일은 넣지 않는다.

### 2.5 1:1 준비 도우미 신청

- 위치: 결과 화면 아래, 탭 밖의 카드.
- 문구: "공공예식장 신청부터 예식까지, 카카오톡으로 같이 준비해 드려요 (무료 시범 운영)".
- 버튼을 누르면 구글폼 미리 채우기 주소로 연다. 결과 요약(시기, 지역, 인원, 장소, 식사, 거주지)을 넣는다.
- 구글폼에서 받는 것: 이름, 연락 방법(카카오톡 ID 또는 전화), 개인정보 수집·이용 동의(6장 2번).
- 폼 주소와 미리 채우기 항목 번호는 소스 맨 위 설정 값 한곳에 둔다. 값이 비어 있으면 카드를 숨긴다.

### 2.6 방문 통계

- 도구: GoatCounter. 쿠키와 개인 식별이 없어 동의 팝업이 필요 없다.
- 세는 지점: `start`(시작), `result`(결과 확인), `share`(공유), `apply`(도우미 신청 클릭).
- 계정 코드는 설정 값 한곳에 둔다. 비어 있으면 통계 스크립트를 넣지 않는다.

### 2.7 바뀌는 파일

| 파일 | 내용 |
|---|---|
| `src/app.src.html` | 거주지 질문, 장소 목록, 공유, 캘린더, 신청 카드, 통계, 설정 값 |
| `src/venues.json` | 새 파일. 공공예식장 목록 |
| `src/build.py` | `venues.json`을 읽어 사이트에 넣는다 |
| `README.md` | 운영자용: 데이터 고치는 법, 설정 값 넣는 법, 다시 빌드하는 법 |
| `tests/flow.test.js` | 새 파일. 휴대폰 크기 브라우저 흐름 테스트 |

### 2.8 테스트

Playwright로 390×844 화면에서 다음을 확인한다.

1. 서울을 고르면 거주지 질문이 나오고, 다른 지역이면 나오지 않는다.
2. 거주지 `y`/`n`/`u`에 따라 지원 줄과 합계가 맞게 바뀐다.
3. 장소 목록이 세부 지역과 하객 수 기준으로 정렬된다.
4. 공유 링크로 들어오면 바로 결과가 나오고, 잘못된 값이면 처음 화면으로 간다.
5. 체크가 새로고침 후에도 남는다.
6. `.ics` 파일에 지나지 않은 할 일만 들어간다.
7. 설정 값이 비어 있으면 신청 카드와 통계가 나타나지 않는다.
8. 되돌아가기 기능(결과에서 항목 고치기, 진행 점, 뒤로가기)이 계속 동작한다.
9. 페이지 오류가 없다.

## 3. 운영 방식

### 3.1 커플 한 쌍을 돕는 순서

| 단계 | 언제 | 운영자가 할 일 |
|---|---|---|
| ① 첫 연락 | 신청 후 24시간 안 | 인사하고 신청 내용(시기, 지역, 인원)을 확인한다 |
| ② 자격·날짜 확인 | 첫 주 | 지원금 자격과 날짜 예약 가능성을 확인하고, 장소 후보 2~3곳을 추린다 |
| ③ 상담 신청 안내 | 1~2주 | 서울시 누리집 상담 신청을 같이 진행한다(대표번호 1899-2154). 미리 물어볼 질문 목록을 준다 |
| ④ 협력업체 계약 점검 | 상담 후 | 견적서의 추가 요금, 위약금 조항을 같이 확인한다 |
| ⑤ 일정 알림 | 예식 90·60·30·14·7일 전 | 이번 주 할 일을 보낸다 |
| ⑥ 예식 후 | 1~2주 뒤 | 실제 지출 설문(5분), 후기, 친구 추천을 부탁한다 |

- 시간 계산: 커플당 주 약 15분 × 20쌍 = 주 5시간.
- 자주 쓰는 메시지(첫 인사, 일정 알림, 예식 후 설문)는 카카오톡 채널 '저장된 답장'에 둔다.

### 3.2 기록 시트

- 열: 커플 번호, 신청일, 예식 시기, 장소 후보, 현재 단계(①~⑥), 다음 연락일, 항목별 예산·실제 지출, 소개 업체, 유료 의향.
- 실명과 연락처는 시트에 적지 않는다. 연락처는 카카오톡 채널 안에만 둔다.

### 3.3 업체 제휴

- 기준(모두 충족): 가격 공개(참가격 또는 홈페이지), 소규모 예식 가능, 공공예식장 경험.
- 처음 4주는 무료로 소개해 실적을 만들고, 실적을 근거로 수수료를 제안한다.
- 제안 예시: 소개 코드 사용 시 고객 5~10% 할인, 운영자 5~10% 수수료. 실제 비율은 협상으로 정한다.
- 수수료를 받는 업체는 고객에게 "제휴 업체(수수료 받음)"라고 밝힌다. 공정위 추천·보증 심사지침에 따른 의무다.
- 서울시 사업의 지정 협력업체와는 경쟁하지 않고 제휴할 수 있는지 먼저 확인한다.

### 3.4 돈 낼 의향 확인 (4주차)

- 무료로 쓰는 커플에게 유료 상품안을 보여주고 반응을 듣는다. 예: "예식 당일까지 동행, 29,000원"
- 실제 결제는 받지 않고, 쓰겠다는 답과 그 이유를 기록한다.

### 3.5 매주 점검 (30분)

- 숫자: 방문 → 결과 → 신청 → 상담 진행.
- 이번 주 가장 많이 막힌 질문 3개.
- 다음 주에 고칠 기능 1개. 막힌 질문을 사이트 안내로 옮기는 일을 우선한다.

## 4. 8주 뒤 판단

| 결과 | 다음 단계 |
|---|---|
| 신청 20쌍과 업체 소개 3건 이상 | 계속: 반복 작업을 웹앱으로 만든다(로그인, 진행 저장, 자동 알림). 지자체 제안서를 준비한다 |
| 신청은 많은데 업체 연결이 안 됨 | 방향 수정: 수익을 커플 대상 유료 상품 쪽으로 옮긴다 |
| 신청 5쌍 미만 | 멈추고 다시 생각: 고객층이나 홍보 채널을 다시 본다 |

## 5. 운영자가 준비할 것

Claude가 대신 만들 수 없는 것들이다.

- 구글폼(질문: 이름, 연락 방법, 동의 체크, 결과 요약 칸)과 미리 채우기 주소
- 카카오톡 채널 개설
- GoatCounter 계정 코드
- 공공예식장 정보의 직접 확인(수용 인원, 대관료, 음식 반입)
- 첫 업체 연락

## 6. 법·개인정보

1. 사업자 등록은 처음 수익(제휴 수수료)이 생기기 전에 한다.
2. 신청서의 개인정보 수집·이용 안내에 다음을 적는다.
   - 수집 항목: 이름, 연락 방법, 예식 정보
   - 목적: 결혼 준비 안내
   - 보관 기간: 예식 후 3개월 뒤 삭제
3. 제휴 업체를 추천할 때는 경제적 이해관계를 밝힌다(3.3).
4. 사이트의 금액은 추정치라는 안내를 유지한다. 공공예식장 정보에는 기준일을 표시한다.
